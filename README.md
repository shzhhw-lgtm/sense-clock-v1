# Sense Clock V1

一款 HTC Sense 风格的原生 Android 桌面时钟小组件，由项目中的 HTML 版时钟移植而来。当前版本为预览版，应用名为 **Sense Clock V1**，包名为 `com.example.senseclockv1`。

采用 **Kotlin + Jetpack Compose** 实现设置界面，通过 **Canvas + RemoteViews** 显示桌面组件。直接使用原版主题图片和静态天气图片，保留翻页钟外观，不播放翻页或天气动画，也不使用 WebView 套壳。

## 功能

- 六套时钟主题：Default、Aluminum、Concrete、Graphite、Matte、Steel。
- 12 / 24 小时制切换，主界面 12 小时预览采用 `PM 04:30` 格式，桌面组件显示 AM / PM 素材。
- 使用设备本地时间，显示日期和星期。
- 和风天气 API 配置：API HOST、API KEY。
- 自动 IP 定位或手动输入固定省市，显示城市、天气、当前温度及预报最高 / 最低温。
- 位置与天气更新频率分别设置，位置默认 2 小时，天气默认 15 分钟。
- 根据天气代码选择静态图片，支持昼夜代码与晴间多云的云量分档。
- 打开 App 自动检查天气新鲜度；强制更新成功后替换旧数据，失败时保留缓存并提示原因。
- 透明背景、等比缩放，自动收紧图片四周的透明边距。
- 设置本地保存，主题、时间格式及天气更新同步到已有组件。
- 点击桌面组件直接进入 App 主界面。
- 提供“闹钟和提醒”及电池策略设置入口。

多个桌面组件共用同一套设置，暂不支持每个组件独立选择主题或城市。

## 系统要求

- Android 12（API 31）及以上。
- 支持 Android 桌面小组件的启动器。
- 时钟显示无需联网；天气需要网络和有效的和风天气 API 配置。
- Android 12 及以上建议允许“闹钟和提醒”，改善分钟切换的及时性。

## 使用方法

### 1. 安装并打开应用

安装已签名的 APK，通过 **Sense Clock V1** 应用图标或已有桌面组件进入主界面。

主界面依次为：

1. **位置 · 实时天气**：城市、天气、更新时间、缓存状态与强制更新。
2. **定位 · 更新频率**：自动定位开关、固定省市和更新周期。
3. **时间格式 · 插件皮肤**：时间格式预览、12 / 24 小时切换和主题选择。
4. **时钟权限设置**：添加组件、准点更新权限、电池策略入口。
5. **和风天气 API 配置**：API HOST、API KEY 和保存按钮。

### 2. 配置天气 API

在和风天气控制台获取个人 API HOST 和 API KEY，并填入应用：

```text
API HOST：控制台提供的域名，例如 xxxxxxxx.qweatherapi.com
API KEY ：自己的 API Key
```

- HOST 可以填写域名，也可以带 `https://` 前缀。
- 不要填写 `/v7/weather/now` 等接口路径、端口或查询参数。
- 点击“保存 API 配置”，配置有效且没有未保存的定位设置时，会按需获取天气；也可点击“强制更新”。
- 同时清空两项并保存，可以停用天气。
- API KEY 支持显示 / 隐藏，请勿将个人密钥放入截图或公开发布的源码。

当前使用和风天气的城市查询、实时天气和三日预报接口，请确认账号拥有对应接口权限。

### 3. 设置定位方式和更新频率

在“定位 · 更新频率”中设置：

- **自动定位（默认开启）**：通过公网 IP 查询省市，位置更新频率可选 **2、6、12、24 小时**，默认 **24 小时**。
- **手动位置**：关闭自动定位后填写省、市，可以精确到区，例如 `江苏 / 南京` 或者 `江苏 / 玄武`；直辖市可填写 `上海 / 上海` 或者 `上海 / 闵行`。应用同时核对省、市/区，匹配不唯一时提示错误，不任意选择城市。固定位置不发起 IP 定位。
- **天气更新频率**：可选 **15 分钟、30 分钟、1 小时、2 小时、6 小时、12 小时**，默认 **15 分钟**。
- 点击 **“保存设置”** 后生效并持久保存。切换位置后尝试获取新位置天气；失败时保留旧位置缓存并明确提示。

### 4. 添加桌面组件与允许后台更新

- 在应用中点击“添加到桌面”，支持此功能的启动器会弹出添加提示。
- 或长按桌面空白处，在小组件列表中找到 **Sense Clock V1** 所属组件；当前组件标签使用“时钟权限设置”。
- 添加后可通过桌面的长按操作调整组件大小，具体方式取决于启动器。

组件默认请求 4×3 格空间，实际占用和外围间距由桌面网格决定。组件保持等比显示，在较宽或较矮的区域中可能仍有留白。

在“时钟权限设置”中点击“允许时钟准点更新”，按系统提示允许“闹钟和提醒”。点击“电池策略设置”进入系统电池优化页面，手动为应用选择“不优化”；部分手机需在应用信息的电池设置中选择“无限制”或“允许后台运行”。不支持电池优化入口时，应用会尝试打开自身应用信息页面。

### 5. 设置时间格式与主题

- 开启“24 小时制”显示 24 小时时间，关闭后显示 12 小时时间与 AM / PM。
- 从下拉菜单选择主题。
- 这两项即时保存，并通知桌面组件更新。
- 时间格式预览用于查看制式，不是完整的桌面主题预览。

## 时间与天气更新

### 时钟

桌面数字是图片素材，需要应用在分钟变化后重新合成图片。应用通过系统 `AlarmManager` 安排下一次整分钟更新，并处理时间修改、时区变化、设备重启和应用更新事件。

Android 12 及以上可从应用中的“允许时钟准点更新”进入系统“闹钟和提醒”设置。未允许时使用非精确调度，可能延迟更新。

**精确闹钟权限不代表任何状态下都能每分钟准时触发。** Doze、系统调度限额以及厂商后台管理仍可能造成延迟；当前实现使用可在空闲状态执行的唤醒闹钟，实际表现和耗电情况取决于设备。

### 位置与天气

| 场景 | 行为 |
| --- | --- |
| 后台周期 | 仅在有桌面组件且 API 配置有效时启用，天气默认 15 分钟，可在界面调整 |
| 自动位置 | 默认每 24 小时到期检查，可调整；未到期时复用独立缓存的城市 ID |
| 固定位置 | 按保存的省、市匹配城市并缓存 ID，不进行周期 IP 定位 |
| 打开或返回 App | 先展示缓存，天气达到 15 分钟、尚无数据或位置需要检查时尝试更新，不要求存在桌面组件 |
| 强制更新 | 跳过天气新鲜度判断；位置仍按到期、缺失或配置变化判断是否重新查询 |
| 位置改变 | 获取新城市天气，即使原来的天气周期尚未到期 |
| 更新失败 | 保留上次成功的数据和时间，在主界面显示失败原因及缓存提示；桌面组件显示“缓存 · 更新时间” |
| 移除全部组件 | 取消组件时间调度和后台天气任务，仍可在打开 App 或手动操作时更新 |

后台通过系统 `JobScheduler` 调度，要求网络可用。自动定位模式按位置与天气周期中较短的周期安排检查，再分别判断哪项数据到期。例如位置设为 24 小时、天气设为 2 小时，位置检查不会每次都请求天气；城市改变时例外。

打开 App 的 **15 分钟新鲜度标准**独立于用户选择的后台天气周期。修改设置后会更新已有调度。主界面没有持续的前台天气轮询。

旧天气不会仅因跨天或超过 24 小时就被删除；过期、失败或位置变化时明确标注缓存，跨天的最高 / 最低温会在主界面注明所属预报日期。成功获取完整新天气后才替换旧快照并清除失败状态。

后台周期是目标检查间隔，网络、Doze、系统调度和厂商电池管理可能推迟执行，选择“无限制”也不保证准点更新。分钟级时钟重绘不发起天气请求。

一次完整刷新会调用多个接口，**不要将一次按钮点击理解为只消耗一次 API 请求额度**，计费和额度以服务商规则为准。

## 定位、网络与数据保存

当前支持中国城市的 **网络出口 IP 自动定位**和**手动固定省市/区**，不使用 GPS，也不申请设备定位权限。

自动定位缓存到期或缺失时的流程：

```text
IPIP.NET 获取省市
    ↓ 主流程失败时尝试 ip-api 备用定位
和风 GeoAPI 匹配城市
    ↓
获取实时天气与当天最高 / 最低温
```

- 主定位服务：`https://myip.ipip.net`。
- 备用定位服务：`http://ip-api.com/json/?lang=zh-CN`。
- 和风天气请求通过 HTTPS 发送，API KEY 放在请求头中。
- 仅对 `ip-api.com` 开放明文 HTTP；不会向该定位服务发送和风 API KEY。
- 城市取决于网络出口，使用 VPN、代理或部分移动网络时可能与实际位置不同。

固定位置通过和风 GeoAPI 按省、市共同匹配；已有可用城市 ID 时，天气更新直接使用该 ID。

设置、凭据、位置缓存和天气缓存保存在应用私有的 SharedPreferences 中。API 凭据以及包含位置缓存的天气缓存文件已排除在系统云备份和设备迁移之外；凭据未额外采用应用层加密。用户手动填写的省市作为设置保存。

应用声明的权限：

| 权限 | 用途 |
| --- | --- |
| INTERNET | 查询定位和天气 |
| ACCESS_NETWORK_STATE | 后台天气任务的网络条件 |
| RECEIVE_BOOT_COMPLETED | 重启后恢复相关调度 |
| SCHEDULE_EXACT_ALARM | 获准后安排更及时的时钟更新 |

## 素材与字体

| 内容 | 实现 |
| --- | --- |
| 时钟数字、上下页片、AM / PM | 六套主题 PNG 素材 |
| 摄氏度符号 | 公共 PNG 素材 |
| 天气图案 | 静态天气 PNG，根据天气代码映射 |
| 日期、星期、城市、天气描述 | `DroidSansFallback.ttf` |
| 当前温度、最高 / 最低温、斜杠 | `Roboto-Regular.ttf` |

桌面组件以原 HTML 的 1200×800 坐标为布局基准，先绘制再裁掉完全透明的外围边距，并保留少量安全空间。主界面使用 Compose 主题字体。

## 构建

项目使用 Android SDK 37、Gradle Wrapper 9.5.0，最低 API 31。Release 当前使用默认 debug 签名，仅适合预览和测试：

```powershell
.\gradlew.bat :app:assembleRelease
```

APK 输出位置：

```text
app/build/outputs/apk/release/app-release.apk
```

当前 Release 已启用优化，并暂时使用默认 **debug 签名**，便于安装测试：

```kotlin
release {
    signingConfig = signingConfigs.getByName("debug")
    optimization {
        enable = true
    }
}
```

这仍是 Release 构建类型，只是使用本机默认 debug 密钥签名，不需要将构建类型改成 Debug。

长期分发前应改为自己保存的 Release 签名密钥。覆盖升级需要包名和签名兼容；不同电脑生成的默认 debug 密钥可能不同。请安装已签名的 APK，不要安装 `app-release-unsigned.apk`。

## 常见问题

### 时间停止更新或慢几秒

先检查“闹钟和提醒”权限与手机的后台运行限制。在部分厂商系统上，还需要允许自启动或调整电池管理。重新从应用图标打开 App 会通知组件刷新并重新安排时间调度。

正常的进程回收通常不会取消已注册的 PendingIntent 闹钟，但厂商清理行为可能额外限制应用；在系统设置中“强行停止”应用后，需重新打开应用恢复运行。

### 点击组件没有反应

当前版本支持点击组件打开主界面。从旧版覆盖安装后，可先通过应用图标打开一次 App，让现有组件更新点击动作。移动、缩放或删除组件仍使用启动器提供的长按操作。

### 天气城市不正确或无法获取

确认 API HOST、API KEY 和接口权限正确。自动定位受 VPN、代理和运营商出口影响，可在“定位 · 更新频率”中关闭自动定位，填写固定省市并保存。固定省市无法唯一匹配时检查名称和所属省份。当前不支持 GPS 定位。

### 没有添加组件，天气是否自动更新

不会启用后台周期任务，但打开或返回 App 时仍会按 15 分钟新鲜度标准检查，也可以手动“强制更新”。有未保存的 API 或定位设置时，请先保存。

### 为什么显示缓存天气

可能是更新失败、天气超过所选周期、预报跨天，或新位置天气尚未成功获取。请留意显示的城市、上次更新时间和错误提示；网络恢复或配置修正后再次更新，成功时会替换缓存。

### 安装提示解析错误或无法覆盖安装

确认 APK 已签名且传输完整，并确认设备为 Android 12 及以上。覆盖安装失败时检查包名和签名是否与旧版本一致；卸载旧版会清除本地配置并移除组件。

### 安装包为什么仍有一定体积

应用保留了六套主题、静态天气 PNG 和中文 TTF 字体。Release 优化可以减少无用代码，但这些实际使用的素材仍会占用空间。删除开发资料或构建缓存不会缩小已生成的 APK。
